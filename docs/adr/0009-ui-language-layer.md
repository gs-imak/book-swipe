# The UI language layer is a module function plus a root remount

`t()` is a plain module function reading a module-level locale, not a hook, because the app has ~1,300 strings across 70 files and threading a hook through every one of them is 70 chances to end up inside a callback, a `map`, or a helper and break the rules of hooks; re-rendering on a language change is handled once at the root instead, where the provider keys the tree on the active locale so a switch remounts everything and every `t()` is evaluated again — heavy-handed per frame, and exactly right for something a reader does once.

Server renders are always the default locale: the active locale lives in a module variable, and on the server a module variable is shared by every concurrent request, so a visitor's language written into it would leak into somebody else's page. The client's first render therefore matches the server (no hydration mismatch) and `useSyncExternalStore`'s client snapshot corrects it on the next commit. The four genuinely server-rendered surfaces — the root layout, the 404, and the two legal pages — use `lib/i18n/server`, whose translator is bound per request from a cookie with `Accept-Language` as the fallback.

Keys are flat and dotted in a plain `Record`, never nested: a nesting resolver splits on `.` and silently returns nothing the first time a key contains a dot that came from data. `fr.ts` is typed as `Record<keyof typeof en, string>`, so a missing translation is a build failure rather than an English word inside a French sentence — there is no runtime check that could tell a missing translation from a deliberately identical one.

Copy that lives in module-scope tables (achievements, challenge prompts, reader archetypes, default shelf names) is translated at the point of RENDER by `tv()`, which looks a string up by its English text. A `t("key")` in those tables would run at import time, before the reader's language is known, and freeze English in for the session; and the English strings are frequently also data — the recommender matches on genre names, the archetype maps are keyed on English genres and moods, and default shelf names are stored identities. Keeping the data English and translating only what is drawn is what lets both be true at once.
